# 现有数据集对 SPIRE SFT 设计 2.4 节支撑能力评估

## 一、设计文档要求的三类数据集

根据 [SPIRE SFT 设计.md](SPIRE SFT 设计.md) 2.4 节，需要以下三类数据集：

| 数据集类型 | 符号 | 说明 | 用途 |
|---|---|---|---|
| **未配对乐谱集** | $\mathcal{D}_{\Sigma}$ | 仅有 score，无对应 performance | Score Language SFT（continuation + mask reconstruction） |
| **未配对演奏集** | $\mathcal{D}_{\Phi}$ | 仅有 performance MIDI，无对应 score | Performance Language SFT（continuation + mask reconstruction） |
| **小节级配对集** | $\mathcal{D}_{\Sigma\Phi}^{M}$ | score-performance 在 measure 级别对齐 | EPR / CSR 主任务（需要高质量配对） |

## 二、现有数据集盘点

### 2.1 PianoCoRe 数据集

**规模：** 250,046 条记录

**数据分布：**
- **配对数据（有 score + performance）：** 161,057 条（64.4%）
- **仅有 performance：** 44,399 条（17.7%）
- **仅有 score：** 61,626 条（24.6%）
- **Refined 高质量配对：** 5 条（极少！）

**关键字段：**
- `score_xml_path`, `score_midi_path`：乐谱文件（MusicXML + MIDI）
- `performance_midi_path`：演奏 MIDI
- `raw_alignment_path`, `refined_alignment_path`：小节级对齐文件（.npz 格式）
- `is_refined`：是否为高质量配对（True 仅 5 条）
- `raw_recall`, `raw_precision`：对齐质量指标

**问题：**
1. ⚠️ **Refined 数据极少**：仅 5 条高质量配对，远不足以支撑 EPR/CSR 训练
2. ✅ **Raw 配对数据充足**：16 万条配对数据，但需要验证对齐质量
3. ✅ **未配对数据充足**：4.4 万 performance-only + 6.1 万 score-only 可用于 Language Learning

### 2.2 ASAP 数据集 + Omnizart Phrase8 处理

**规模：** 1,293 个 MIDI-TSV 文件（10,819 个 phrases）

**数据格式：** MIDI-TSV（已切分为 phrase，4-8 measures 占 90.3%）

**关键特性：**
- ✅ 已用 Omnizart 自动检测 downbeat 并切分小节
- ✅ 已用启发式算法切分 phrase（符合设计文档 4.2 节要求）
- ✅ 包含 measure 和 phrase 边界标注（`M1`, `H1` 等）
- ⚠️ 13 个文件转换失败（Omnizart 未检测到 downbeat）

**用途：** 可直接用于 **Performance Language SFT**（$\mathcal{D}_{\Phi}$）

### 2.3 Maestro Score v1 数据集

**规模：** 1,276 个 MAESTRO performance MIDI + 835 个乐谱文件

**乐谱格式：** MusicXML / MXL（原始格式）

**已转换格式：**
- `maestro_score_v1_abc/`：152 个 ABC 文件（非 ABCX）
- `maestro_score_v1_abc_legato/`：部分 JSON 格式转换日志

**问题：**
1. ⚠️ **缺少 ABCX 格式**：现有 ABC 文件不是 ABCX（设计文档要求的 score 语言）
2. ⚠️ **缺少小节级对齐**：MAESTRO 原始数据集无 score-performance 对齐标注
3. ✅ **乐谱资源丰富**：835 个 MusicXML 文件可转换为 ABCX

### 2.4 ABC from XML 数据集

**规模：** 234 个 ABCX 文件（从 ASAP 的 MusicXML 转换）

**覆盖作曲家：** Bach, Beethoven, Brahms, Chopin, Debussy, Glinka, Haydn, Liszt, Mozart, Schumann 等

**用途：** 可直接用于 **Score Language SFT**（$\mathcal{D}_{\Sigma}$）

## 三、三类数据集支撑能力评估

### 3.1 未配对乐谱集 $\mathcal{D}_{\Sigma}$ ✅ **基本满足**

| 数据源 | 数量 | 格式 | 可用性 |
|---|---|---|---|
| PianoCoRe score-only | 61,626 | MusicXML + MIDI | ✅ 需转换为 ABCX |
| ABC from XML | 234 | ABCX | ✅ 直接可用 |
| Maestro Score v1 | 835 | MusicXML | ✅ 需转换为 ABCX |

**总计：** ~62,695 个乐谱（需转换为 ABCX）

**处理需求：**
1. ✅ 已有转换工具（`xml_to_abcx.py`）
2. ⚠️ 需批量转换 PianoCoRe 和 Maestro Score 的 MusicXML → ABCX
3. ✅ 转换后可用启发式算法切分 phrase（设计文档 4.1 节）

### 3.2 未配对演奏集 $\mathcal{D}_{\Phi}$ ✅ **满足**

| 数据源 | 数量 | 格式 | 可用性 |
|---|---|---|---|
| PianoCoRe performance-only | 44,399 | MIDI | ⚠️ 需转换为 MIDI-TSV + phrase 切分 |
| ASAP Omnizart Phrase8 | 1,293 (10,819 phrases) | MIDI-TSV | ✅ 直接可用 |

**总计：** ~45,692 个 performance MIDI

**处理需求：**
1. ✅ ASAP Phrase8 已完成 Omnizart downbeat 检测 + phrase 切分
2. ⚠️ PianoCoRe performance-only 需要：
   - 用 Omnizart 检测 downbeat
   - 转换为 MIDI-TSV
   - 启发式 phrase 切分

### 3.3 小节级配对集 $\mathcal{D}_{\Sigma\Phi}^{M}$ ⚠️ **严重不足**

| 数据源 | 数量 | 对齐质量 | 可用性 |
|---|---|---|---|
| PianoCoRe refined | 5 | 高质量（refined） | ✅ 直接可用但数量极少 |
| PianoCoRe raw paired | 161,057 | 中等质量（raw） | ⚠️ 需验证对齐质量 |
| Maestro Score v1 | 1,276 | 无对齐标注 | ❌ 需重新对齐 |

**关键问题：**
1. ❌ **Refined 数据极少**：仅 5 条高质量配对，无法支撑 EPR/CSR 训练
2. ⚠️ **Raw 配对质量未知**：16 万条 raw 配对数据，但 `raw_recall` 和 `raw_precision` 分布未知
3. ⚠️ **需要质量过滤**：根据设计文档 4.3 节，需要过滤出对齐可靠的配对数据

**处理需求：**
1. **验证 PianoCoRe raw 配对质量**：
   - 统计 `raw_recall` 和 `raw_precision` 分布
   - 设定阈值（如 recall > 0.85, precision > 0.75）过滤高质量配对
   - 检查 measure 数量是否匹配、边界偏移是否过大
2. **转换为 ABCX + MIDI-TSV**：
   - Score: MusicXML → ABCX
   - Performance: MIDI → MIDI-TSV（用 alignment 信息切分 measure）
3. **Phrase 级切分**：
   - 以 score 为主轴切分 phrase
   - 根据 measure 级对齐将 performance 也切分成对应 phrase
   - 质量控制：phrase 级对齐质量差的降级为未配对数据

## 四、数据处理优先级建议

### Phase 1：验证现有配对数据质量（最高优先级）

```bash
# 1. 统计 PianoCoRe raw 配对数据的对齐质量分布
awk -F',' 'NR>1 && $6!="" && $16!="" {print $24,$25}' PianoCoRe/metadata.csv | \
  awk '{if($1>0.85 && $2>0.75) high++; else low++} END {print "High quality:", high; print "Low quality:", low}'

# 2. 过滤高质量配对（recall > 0.85, precision > 0.75）
awk -F',' 'NR>1 && $6!="" && $16!="" && $24>0.85 && $25>0.75' PianoCoRe/metadata.csv > high_quality_pairs.csv
```

### Phase 2：转换 Score 为 ABCX

```bash
# 1. 转换 PianoCoRe score-only
python xml_to_abcx.py --input PianoCoRe/ --output data/pianocore_abcx/

# 2. 转换 Maestro Score v1
python xml_to_abcx.py --input data/maestro_score_v1/works/ --output data/maestro_score_v1_abcx/

# 3. 转换 PianoCoRe 高质量配对的 score
python xml_to_abcx.py --input high_quality_pairs.csv --output data/pianocore_paired_abcx/
```

### Phase 3：转换 Performance 为 MIDI-TSV + Phrase 切分

```bash
# 1. 转换 PianoCoRe performance-only（用 Omnizart）
python scripts/score_corpus_pipeline.py \
  --input PianoCoRe/performance_only/ \
  --output data/pianocore_performance_tsv/ \
  --phrase-length 8

# 2. 转换 PianoCoRe 高质量配对的 performance（用 alignment）
python scripts/convert_paired_performance.py \
  --input high_quality_pairs.csv \
  --output data/pianocore_paired_tsv/ \
  --use-alignment
```

### Phase 4：生成训练样本

```bash
# 1. Score Language samples（continuation + mask）
python scripts/generate_score_language_samples.py \
  --input data/pianocore_abcx/ data/maestro_score_v1_abcx/ data/abc_from_xml/ \
  --output data/sft_samples/score_language/

# 2. Performance Language samples（continuation + mask）
python scripts/generate_performance_language_samples.py \
  --input data/asap-dataset-omnizart-phrase8/ data/pianocore_performance_tsv/ \
  --output data/sft_samples/performance_language/

# 3. EPR / CSR samples（paired）
python scripts/generate_epr_csr_samples.py \
  --input data/pianocore_paired_abcx/ data/pianocore_paired_tsv/ \
  --output data/sft_samples/epr_csr/
```

## 五、结论与建议

### 5.1 当前状态

| 数据集类型 | 状态 | 数量估计 | 瓶颈 |
|---|---|---|---|
| $\mathcal{D}_{\Sigma}$ 未配对乐谱 | ✅ 基本满足 | ~62,695 | 需转换为 ABCX |
| $\mathcal{D}_{\Phi}$ 未配对演奏 | ✅ 满足 | ~45,692 | 需转换为 MIDI-TSV + phrase 切分 |
| $\mathcal{D}_{\Sigma\Phi}^{M}$ 小节级配对 | ⚠️ 严重不足 | 5 refined + ? raw | **需验证 raw 配对质量** |

### 5.2 关键风险

1. **配对数据质量未知**：PianoCoRe 的 16 万条 raw 配对数据质量分布未知，可能大部分不满足 EPR/CSR 训练要求
2. **Refined 数据极少**：仅 5 条高质量配对，如果 raw 配对过滤后数量仍不足，需要考虑：
   - 降低质量阈值（但可能影响 EPR/CSR 效果）
   - 使用 Maestro Score v1 重新对齐（工作量大）
   - 减少 EPR/CSR 训练数据量，增加 Language Learning 比例

### 5.3 下一步行动

**立即执行：**
1. ✅ 统计 PianoCoRe raw 配对数据的 `raw_recall` 和 `raw_precision` 分布
2. ✅ 设定质量阈值，过滤出高质量配对数据
3. ✅ 评估过滤后的配对数据量是否足够（建议至少 5k-10k 条）

**如果配对数据充足（> 5k）：**
- 按 Phase 1-4 执行数据处理流程
- 优先完成 Language Learning SFT（Step 1）
- 再进入 EPR/CSR 分支（Step 2a/2b）

**如果配对数据不足（< 5k）：**
- 考虑使用 Maestro Score v1 重新对齐（需要开发对齐工具）
- 或调整训练策略：增加 Language Learning 比例，减少 EPR/CSR 数据需求
- 或使用数据增强：同一 score 配对多个 performance（如果有）

### 5.4 格式处理能力

**现有工具：**
- ✅ `xml_to_abcx.py`：MusicXML → ABCX
- ✅ `scripts/score_corpus_pipeline.py`：MIDI → MIDI-TSV + Omnizart phrase 切分
- ⚠️ 缺少：基于 alignment 的配对数据转换工具

**需要开发：**
1. **配对数据转换工具**：读取 PianoCoRe alignment (.npz)，将 score + performance 转换为 ABCX + MIDI-TSV
2. **质量过滤工具**：根据 recall/precision/measure 匹配度过滤配对数据
3. **训练样本生成工具**：根据设计文档 3.1-3.4 节生成各类任务样本

---

**总结：** 现有数据集在 **未配对数据** 方面基本满足需求，但 **配对数据** 存在严重不足风险。**最紧急的任务是验证 PianoCoRe raw 配对数据的质量分布**，这将决定整个训练流程的可行性。
