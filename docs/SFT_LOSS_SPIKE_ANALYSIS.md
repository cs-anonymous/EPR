# SFT Loss 分析：train_S3 → train_Astar1 突然上涨

## 现象

在 train_S3 结束进入 train_Astar1 时，loss 从 **1.2651** 突然上升到 **1.3254**（上涨 **0.06**，约 **4.8%**）

## 验证：排除的可能原因

### ✅ 1. 不是模型重新加载
- 训练脚本：`"continuous_without_reload": True`
- 模型权重连续传递

### ✅ 2. 不是学习率重置
```
Step 12680 (train_S3):    lr = 3.553233e-05
Step 12700 (train_Astar1): lr = 3.548821e-05
```
学习率平滑衰减，无跳变。

### ✅ 3. 不是"专业 vs 业余"演奏差异

**重要澄清**：之前误解了数据来源！

| 数据集 | ASAP 专业演奏 | 业余演奏 (Aria/PERiScoPe) |
|--------|--------------|--------------------------|
| train_S3 | **3.1%** | **96.9%** |
| train_Astar1 | **0%** | **100%** |

**关键事实**：
- `piece_id` 包含 "ASAP" ≠ ASAP 专业演奏
- 那只是说明**乐谱**来自 ASAP 数据集（~1000 首曲子）
- 真正的演奏来源看 `performance_id`
- **两个数据集本质都是业余演奏转录**

### ❌ 4. 平均 token 差异不显著

| 指标 | train_S3 | train_Astar1 | 差异 |
|------|----------|--------------|------|
| 平均 total tokens | 3627 | 3746 | +119 (+3.3%) |
| 平均 input tokens | 1930 | 2024 | +94 (+4.9%) |
| 平均 output tokens | 1698 | 1713 | +15 (+0.9%) |

差异存在但不大，不足以完全解释 4.8% 的 loss 上涨。

## 🔑 真正的原因：数据复杂度和分布差异

### 关键发现 1：Token 密度显著增加

| 指标 | train_S3 | train_Astar1 | 差异 |
|------|----------|--------------|------|
| **Token 密度** (tokens/measure) | **191.8** | **230.8** | **+38.9 (+20.3%)** ⚠️ |
| 密度标准差 | 83.9 | 114.2 | +30.2 (+36.0%) |

**解读**：
- Astar1 的音符密度**高 20%**！
- 标准差增加 36%，说明数据**更不均匀**
- **更密集的音符 = 更难预测 = loss 更高**

### 关键发现 2：Output/Input 比例降低

| 指标 | train_S3 | train_Astar1 | 差异 |
|------|----------|--------------|------|
| Output/Input 比例 | **0.892** | **0.863** | **-0.029 (-3.3%)** |
| 比例标准差 | 0.236 | 0.246 | +0.010 (+4.2%) |

**解读**：
- Astar1 的演奏相对乐谱**更简单/更接近原谱**
- 但标准差更大，说明**一致性更差**
- 低比例 + 高方差 = 更难预测的模式

### 关键发现 3：作曲家分布剧烈变化

**train_S3 作曲家分布**：
```
Beethoven  25.9%
Chopin     23.6%
Bach        9.4%
Mozart      8.9%
Debussy     5.6%
```
相对均衡，前 5 位占 73%

**train_Astar1 作曲家分布**：
```
Chopin     39.2%  ⚠️ 暴增！
Beethoven  12.7%  ⬇️ 减半
Liszt      11.4%  ⚠️ 新进前 3
Debussy     7.3%
Schubert    5.3%
```
**Chopin 独占 39%**，前 5 位占 76%

**影响**：
- 模型在 S1/S2/S3 学习了相对均衡的风格分布
- Astar1 突然遇到 **Chopin 占主导** 的数据
- 风格偏移导致初期 loss 上涨

### 关键发现 4：数据覆盖率差异

| 指标 | train_S3 | train_Astar1 | 差异 |
|------|----------|--------------|------|
| Unique pieces | 1,026 | 939 | -87 |
| Samples/piece | 98.9 | 175.6 | **+76.7 (+77.5%)** |

**解读**：
- Astar1 虽然曲目更少，但**每首曲子的样本密度高 77%**
- 说明 Astar1 对某些曲目**过度采样**
- 可能导致局部过拟合和泛化性下降

## 综合分析

### 为什么 loss 会上涨？

**多因素叠加效应**：

1. **数据复杂度骤增** (+20% token 密度)
   - 更密集的音符 → 更多细节需要预测
   - 标准差大 → 复杂度不均匀，难以优化

2. **风格分布剧变** (Chopin 从 23.6% → 39.2%)
   - 模型在 S 轮学习的均衡分布被打破
   - 突然遇到 Chopin 主导的数据
   - 需要重新适应新的风格权重

3. **数据采样密度变化** (+77% samples/piece)
   - Astar1 对少数曲目过度采样
   - 训练早期可能导致局部模式过拟合
   - 泛化能力暂时下降

4. **Output/Input 比例变异增加**
   - 虽然平均比例降低（更简单）
   - 但标准差增大（更不一致）
   - 预测难度反而上升

### 类比

这类似于：
1. 学生在**均衡题库**上训练（S1/S2/S3）
2. 突然遇到**Chopin 专项题库**（Astar1）
3. 题目虽然不难，但：
   - 音符密度更高（细节更多）
   - 风格单一但变化大（标准差高）
   - 同一首曲子反复出现（过度采样）
4. 初期不适应 → 分数下降
5. 逐渐适应后 → 分数回升

## 验证：后续收敛

```
Step 12700: 1.3254  (开始，遇到新的数据分布)
Step 12880: 1.3077  ⬇️ -0.0177 (逐渐适应)
Step 19560: 1.2741  ⬇️ -0.0513 (成功收敛)
```

模型最终成功适应了 Astar1 的特点：
- 更高的 token 密度
- Chopin 主导的风格分布
- 更高的采样密度

## 结论

✅ **Loss 上涨是数据筛选标准不同导致的多维度分布差异**

**核心原因**：
1. ❌ 不是模型重新加载
2. ❌ 不是学习率重置
3. ❌ 不是专业 vs 业余演奏
4. ❌ 不是简单的序列长度差异
5. ✅ **是数据复杂度、风格分布、采样密度的综合差异**

**S-tier vs Astar 的本质区别**：
- S-tier：严格筛选 → 质量高、均衡、复杂度适中
- Astar：宽松标准 → 保留更多边缘样本、风格偏向、复杂度高且不均

这种差异是**筛选标准不同**的必然结果，属于正常现象。

## 建议

如果想减少这种 loss 波动，可以考虑：

1. **交错训练**：S 和 Astar 数据混合，而不是分轮
2. **渐进式混合**：逐渐增加 Astar 比例
3. **风格平衡**：在分轮时保持作曲家分布一致性
4. **控制采样密度**：限制每首曲子的最大样本数

但目前的分轮训练也有优势：
- 可以清晰观察不同质量数据的学习效果
- 便于调试和分析
- 最终收敛效果良好
