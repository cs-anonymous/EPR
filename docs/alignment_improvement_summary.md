# 小节对齐算法改进总结

## 问题分析

原算法（`align_measures.py`）存在以下问题：

1. **使用pitch class（0-11）而不是绝对pitch**：丢失了八度信息
2. **完全忽略音符时长**：只看音高，不看时长
3. **依赖GT reference**：Without GT Reference准确率只有1.8%
4. **GT reference被用在算法中**：GT应该只用于评估，不应该用在算法逻辑中

## 改进方案

### 新算法设计（`align_measures_final.py`）

**核心改进：**

1. **使用绝对pitch**：
   - 从ABCX中提取绝对MIDI pitch（考虑八度标记`,`和`'`）
   - 例如：`C` = MIDI 48, `c` = MIDI 60, `C,` = MIDI 36, `c'` = MIDI 72

2. **保留原算法的匹配逻辑**：
   - 多组件评分函数：set recall + first note match + precision + ordered prefix
   - 这个逻辑在有GT时准确率95%，说明是有效的

3. **改进位置估计**：
   - 基于音符数量的加权估计（而不是简单的均匀分布）
   - 更宽的搜索范围（+/- 50%而不是固定范围）

4. **完全不使用GT reference**：
   - GT只用于评估结果
   - 算法完全独立运行

## 分析

### 成功之处

1. **显著提升**：从1.8%提升到11.8%（精确匹配），提升了6.5倍
2. **容错性好**：在tolerance=100时达到61.8%，说明大部分小节的位置是接近正确的
3. **完全独立**：不依赖任何GT reference

### 仍存在的问题

1. **误差累积**：当一个小节匹配错误时，会影响后续小节的搜索范围
2. **准确率仍然不够高**：11.8%的精确匹配率对于实际应用来说还不够
3. **搜索策略**：当前的贪心搜索（从前一个小节之后开始）限制了纠错能力

### 进一步改进方向

1. **使用音符时长信息**：
   - 当前算法虽然提取了时长，但在匹配时没有充分利用
   - 可以计算小节的总时长，用于更准确的位置估计

2. **改进搜索策略**：
   - 使用全局搜索而不是局部搜索
   - 允许算法"回头"纠正之前的错误

3. **使用更复杂的匹配算法**：
   - 动态时间规整（DTW）
   - 隐马尔可夫模型（HMM）
   - 序列对齐算法（如Smith-Waterman）

4. **多次迭代**：
   - 第一次运行得到粗略对齐
   - 使用粗略对齐结果改进位置估计
   - 第二次运行得到精细对齐

## 使用方法

```bash
# 保存结果
python3 align_measures_final.py score.abcx performance.mid -o output.txt

python3 quick_eval.py
```

## 结论

新算法成功地：
- ✅ 使用了绝对pitch而不是pitch class
- ✅ 提取了音符时长信息（虽然还没有充分利用）
- ✅ 完全不依赖GT reference
- ✅ 准确率从1.8%提升到11.8%（6.5倍提升）

但仍需改进：
- ❌ 准确率仍然不够高（目标应该是>80%）
- ❌ 没有充分利用时长信息
- ❌ 搜索策略需要优化

**建议**：继续改进算法，重点是：
1. 充分利用时长信息进行匹配
2. 改进搜索策略，允许全局搜索和纠错
3. 考虑使用更复杂的序列对齐算法
